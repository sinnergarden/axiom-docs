# 两角色教程叙事重写提案

本提案用于先判断教学主线与示范段落。尚未改动 Notebook，也没有重新执行教学代码。真实例子沿用现有保存输出，工程细节在需要核对时展开；当前代码交付仍由 current-delivery 与 versions.json 统一记录。

## 一页章节主线

Researcher 从“我要把价格和当时可见财报变成可重复的研究输入”出发；Developer 从“我要接入日线，检查并发布，再把修正和失败处理好”出发。两份教程分别完成这一次工作，不按模块目录逐项介绍。

| 推进 | Researcher：一次真实研究的工作过程 | Developer：一次数据接入与维护的工作过程 |
|---|---|---|
| 1 | **确定这次研究要取什么**：说明后面要形成怎样的输入；先用三只股票六个交易日核对读法，财报阶段换到已有两证券完整来源样本。固定数据版本和读取窗口，初始化展开。 | **明确接入范围与字段**：以已有 Tushare 日线为例，先确定证券、日期、所需列与单位，再选择合同和来源映射。 |
| 2 | **取出第一张可以计算的表**：一只证券的 open/close/volume 查询与六行实际结果，再扩为三只证券 close 矩阵。读者先看到参数怎样决定结果。 | **保存并检查一次供应商响应**：沿真实 daily Raw 对象、请求和 receipt，区分响应内容与本次接收；用已保存响应检查，不重新采集。 |
| 3 | **把价格变成可比较的输入**：从刚才的 close 出发，检查单位、缺价/状态、复权因子和共同锚点；说明为何这六天因子比为 1、第一天 return 缺失。详细状态表和来源证明展开。 | **把来源字段映射成日线**：对照真实 Raw 和 Parquet 行，核对 vol 手→股、amount 千元→元、证券键/时间/类型，再看分区；schema 与文件摘要展开。 |
| 4 | **给价格加一列财报信息**：使用已有 600000.SH 收入报告，不把报告期当可用日期；接着从累计值计算单季/TTM，解释实际缺组件结果。 | **让消费者检查，再发布版本**：用 Reader 的查询/单位/可见性结果核对这次接入，再解释 Snapshot 如何引用已检查分区、何时推进 current；失败不会提前发布。 |
| 5 | **回到当时，究竟能看见哪份报告**：由上一节的财报需求引入 cutoff、真实实收与供应商日期假设；真实查询和清楚标注的同公告日修订反例并列，不把终态历史当初版。 | **扩展到财报、事件和 ETF**：沿同一个接入过程处理原生报告键、事件日期与基金单位；遇到新语义再补合同，不把所有数据硬塞成日频股票表。 |
| 6 | **选择当日候选，而不丢预热历史**：沿实际成员查询决定参考截面，保留供应商快照日期和延续含义；窗口与池内过滤各自明确。 | **继续日更，并处理历史修订**：从已有计划观察 monthly batching、checkpoint 和 daily/refresh 的不同范围；小样本证据与十二年作业分开。 |
| 7 | **构建特征，再重复一次实验**：把已有两行情/三财务查询组成十二行联合输入，跟踪这六天收入报告期切换；保存 FeatureBuild，换 Data 实例、跨进程复用；Qlib 作为有需求时的消费支线。 | **改字段、改证券，复用已有 Raw**：先看需求变在哪一层，再走现有 A→A+B 合成离线扩标、字段扩展和整域 Raw 闭包；合成范围明确，不与真实供应商输出混写。 |
| 8 | **把固定输入交给下游**：以现有七 ETF 数据说明完整日历/预热、因子、分红与 UNKNOWN；接到已验 Research→Engine→只读报告，区分信号、意图和成交。这里引用 owner 保存证据，不暗示本教程旧代码已经执行新回测。 | **从失败处恢复，修正并留下旧版本**：沿中断、半写、缺文件和错误映射选最小动作，检查恢复后的固定查询；搬移与修复也围绕这次接入结果判断。 |
| 9 | **加特征或修正数据后，旧实验怎么办**：回到已保存实验，说明配方变更、Raw 缺失、映射/Reader 修正各使哪些结果需要重算，旧输入与旧输出如何保留作对照。 | **交给 Research/Engine 并独立运行**：在前面已发布版本上交接 Query/Reader/Qlib，保留真实版本绑定；环境、部署、完整验证目录放附录。 |

主线每节遵循“本次要做什么 → 实际调用与输出 → 这一步怎样影响下一步”。保留研究所需的价格口径、缺失与时间假设；来源长表、长 hash、安装包、全量限制与跨仓 ABI 放展开附录，不在每节重新列一遍。股票/完整来源/ETF 是三份不同已存样本，切换处交代原因与实际证券，不能叙述成同一套完整全历史数据。

## Researcher 第 2 节：完整示范重写

### 2. 取出第一张可以计算的表

先从这次研究要用的价格开始。我们已经在上一节固定了一年行情样本，现在取 `000001.SZ` 在 2026-08-24 至 08-31 的六个交易日，看看开盘、收盘和成交量，再把同样的读取方式扩到三只证券。

六天是这次核对读法的窗口；样本本身覆盖 2025-09-01—2026-08-31 的 242 个交易日。后续需要较长 lookback 时，应从这份已存日历选择足够的历史，不能拿下面六行直接计算 20D 特征。

本节沿用初始化中已经选定的 `DATA` 和 `SNAPSHOT`。`SYMBOL` 是 `000001.SZ` 的稳定身份，`DAYS` 是以下六个交易日。查询只需要固定这些参数：

| 参数 | 本次取值 | 它决定什么 |
|---|---|---|
| domain | `market_daily` | 读取日线事实 |
| fields | `open`、`close`、`volume_shares` | 返回开盘、收盘和成交股数 |
| symbols | `(SYMBOL,)` | 这一步先只取 `000001.SZ` |
| sessions | 08-24、08-25、08-26、08-27、08-28、08-31 | 六行对应的交易日 |
| cutoff | 每个交易日当日 20:30，UTC+08:00 | 本次收盘后研究允许使用信息的截止时刻 |
| pit_policy | `best_effort_vendor_v1` | 沿用样本声明的供应商历史可用时间假设 |

这里的 cutoff 不是采集时间，也不是交易执行时间。我们先用这个口径读历史日线；加入财报时，再用具体报告解释供应商日期假设和系统实际收到时间为何会得到不同结果。

```python
q = QuerySpec('market_daily', ('open','close','volume_shares'), (SYMBOL,),
    DAYS, 'best_effort_vendor_v1', {d:d+'T20:30:00+08:00' for d in DAYS})
batch = DATA.read(snapshot=SNAPSHOT, query=q)
display(batch.frame)
print('单位:', {k:v['unit'] for k,v in batch.field_meta.items()})
```

这是已有代码的真实保存输出，下面把重复的证券身份列移到表头，便于读数。证券为 `000001.SZ`，稳定键为 `cnstock.000001.SZ.19910403`：

| session | open | close | volume_shares |
|---|---:|---:|---:|
| 2026-08-24 | 11.38 | 11.56 | 119902495 |
| 2026-08-25 | 11.57 | 11.59 | 99488115 |
| 2026-08-26 | 11.55 | 11.73 | 116728878 |
| 2026-08-27 | 11.70 | 11.59 | 97570170 |
| 2026-08-28 | 11.54 | 11.65 | 83812624 |
| 2026-08-31 | 11.64 | 11.72 | 90885655 |

返回的单位是：

```text
{'open': 'CNY/share', 'close': 'CNY/share', 'volume_shares': 'shares'}
```

这张表里，价格是未复权的每股人民币价格，成交量已经是股数。进入量价特征时，直接使用 `volume_shares`；不能再按供应商原始“手”的单位乘一次 100。后续计算使用 `batch.frame`，字段单位与来源则留在同一个 `batch` 里，读数有疑问时再展开核对。

这六天恰好没有缺值，并不表示任意证券或日期都完整。也先不要把 `close.pct_change()` 当作最终收益输入：下一节会把当前收盘、复权因子与缺失状态放在一起，确认用于比较的价格尺度。

#### 扩成三只证券的收盘矩阵

单只证券的字段和单位对上后，继续取 `000001.SZ`、`600000.SH`、`600519.SH` 的 close。调用仍是同一个 Reader；变的是证券集合和字段集合，不必为这三只证券另建存储文件。

```python
panel = DATA.read(snapshot=SNAPSHOT, query=query(('close',),
    symbols=tuple(IDS[c] for c in ('000001.SZ','600000.SH','600519.SH'))))
display(panel.frame.pivot(index='session', columns='security_id', values='close'))
```

`query()` 是初始化中封装的同一组 `DAYS`、收盘后 cutoffs 与历史 policy。下面沿用实际结果，仅把列标签缩短为显示代码：

| 2026-08-25 | 11.59 | 9.08 | 1304.00 |
| 2026-08-26 | 11.73 | 9.21 | 1302.80 |

这是后续按证券计算或按日做横截面处理的输入形状。存储与读取仍保留 `(security_id, session)` 键；这里的宽矩阵只是按键展开的研究视图。它没有自动做复权、填缺失或生成特征。

#### 需要再加字段时

如果下一步要把成交额加入量价特征，先查这个 Snapshot 的字段字典，确认它的规范名、单位和是否接入，再加到 `fields`。本样本的已保存字典输出能看到 `open`、`close`、`volume_shares` 和因子；收入 `total_revenue` 显示“支持但该 Snapshot 未接入”。因此，加入财报时我们会切换到已有的两证券完整来源样本，而不是往这个日线查询里塞一个收入字段。

字段字典和原始映射表可以按需展开；这一节先保留刚取得的两张表。接下来从 `000001.SZ` 的 close 出发，决定哪些值能直接用于比较、哪些空值需要保留、以及共同锚点怎样影响收益计算。

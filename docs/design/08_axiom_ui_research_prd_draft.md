## 1 目标用户与研究问题

目标用户是与 dot 一起研究策略的个人研究者。用户提出 idea，dot 在另行授权的任务中实现并检查；工作台让用户看懂已保存结果，决定保留、否定或修改假设。首版围绕一个实验及其相关运行，避免先做完整研究平台。

用户需要回答：这轮检验什么、改了什么；相对基准和旧版是否改善；收益与风险集中在哪里；为什么在某日买卖或没有成交；证据是否来自同一批固定输入；下一轮只改什么。成功标准是用户能从结果指出证据和下一步，而非曲线达到收益目标。

## 2 从 idea 到下一轮的用户流程

| 步骤 | 用户操作 | 页面给出的结果 |
|---|---|---|
| idea | 与 dot 明确假设、对照和拟改因素 | Research 保存实验说明；UI 读取已有记录，不启动计算 |
| 实验列表 | 默认看近期结果，按研究问题→实验版本→运行浏览；按标签/状态、收藏或搁置筛选 | 看见成功、失败、阻断和负结果；不会只列赢家 |
| 单次回测 | 打开一个运行 | 上下文固定；先看收益风险与主要限制，再下钻细节 |
| 回测结果对比 | 在收益风险视图加旧版或市场基准 | 共用图和指标区展示保存结果；公共配置折叠，只提醒实际差异 |
| 变动与结果复盘 | 选变动项、异常日、月份、持仓段或成交点 | 并列查看变动清单与结果，定位证券、日期及交易链；UI 不生成因果结论 |
| 下一轮 | 复制本轮上下文、证据位置与拟改因素 | 得到可交给 dot 讨论的摘要；新实验仍由 Research 任务创建，UI 不重跑 |

所有视图保留同一实验、运行和版本上下文。返回总览不重置选择；显式换运行后图表和侧栏一起切换。F01 图展示实验与版本的关系。

## 3 六组功能提案

### F01 实验说明与版本

- **输入与展示：**Research 保存的研究问题、实验版本、运行、假设、参数、输入输出版本、变动清单与限制，及实验标签、收藏/搁置标记。按研究问题→实验版本→运行组织，默认近期结果。
- **操作与结果：**按标签或状态筛选、浏览收藏/搁置分组、选版本并打开运行；复制上下文用于下一轮。收藏/搁置是 Research 的记录，UI 展示和筛选已有标记，不通过删除隐藏失败。
- **缺失与 owner：**未保存的说明显示“未提供”，不从参数编造假设。Research 提供记录和关联，UI 导航。**验收要求：**正、负、失败、阻断、收藏和搁置样例都可找到；切换后全部面板指向同一运行，原记录不变。

![F01 实验列表与版本关系，合成示意](ui-prd-assets/figure01_experiment_versions.svg)

### F02 回测结果对比

- **输入与展示：**所选运行、旧版及 Engine 保存的市场基准和比较结果，Research 保存的版本变动清单。F02/F03 共用收益风险图与指标区：一个运行看表现，加旧版/基准即进入比较，不再画两套页面。
- **操作与结果：**选择对照、开关曲线、点日期，得到保存原值和差异。日常沿用 Research 固定的共用区间、资金、费用及滑点配置；详情默认折叠，只在不同处提醒。公共设置不是 UI 重新回测的参数表。
- **缺失与 owner：**未保存基准则标不可用；配置差异注明“非同口径”，不静默裁剪、换汇或重算。Engine 提供账户评估及基准，Research 提供变动与运行关联，UI 展示和联动。**验收要求：**加/删对照不换当前运行，不生成第二套收益风险面板；兼容样例等于保存值，差异提醒能定位具体字段。

![F02 共用收益风险视图添加市场基准，合成示意](ui-prd-assets/figure02_comparison.svg)

### F03 收益与风险

- **输入与展示：**Engine 保存的净值、标准指标及回撤序列。总览显示期间收益、最大回撤、费用、成交额与净值；风险区与净值共用时间轴，接收 F02 所选对照。Qlib 参考中的成本和换手图层在 owner 提供后按需开启。
- **操作与结果：**悬停看日期及原值，选择异常区间，跳转该区间复盘。筛选仅定位；区间指标若未保存，不在前端另算。
- **缺失与 owner：**缺指标或序列时分别显示不可用，不补零；短样本不补年化或 Sharpe。Engine 定义和计算，UI 格式化。**验收要求：**数值、符号和单位与 owner 相等；严格阻断的零成交运行及日线近似运行有明确身份，处理完成不代表策略有效。

### F04 K 线与交易复盘

- **输入与展示：**绑定该运行的 Data OHLC、成交量及 Engine 保存的持仓、决策、委托、成交。价格图叠加成交点和持仓区间；侧栏分开信号日、决策日与成交日。
- **操作与结果：**选择证券、日期或 B/S 点，侧栏显示原价量、费用和已保存执行原因；未成交记录显示阻断原因。图层开关不换版本。**低优先级增强：**查看当时特征、模型分数及版本、候选排名、门槛、买卖触发条件和执行原因，沿已有链展开决策 debug。
- **缺失与 owner：**缺 high/low 就提示 K 线不可用，可展示明确命名的现有价格线；缺 trace 显示未保存，不补事后理由。Data 提供行情，Research 提供保存的特征/信号/模型分数，Core 产生结构化决策依据，由运行方随 run 固定保存，Runtime 提供成交/拒单依据；UI 只读。**验收要求：**点值可逐键对应原记录；意图、拒单和部分成交不会被画成同一种成交点；复权坐标不能改写原成交价。debug 尚未实现，不成为首版阻断条件。

![F04 价格与交易复盘，合成示意](ui-prd-assets/figure04_trade_replay.svg)

### F05 月收益与持仓段统计

- **输入与展示：**Engine 保存的年份×月份账户收益率（百分比）、完整持仓段净盈亏分布、平均收益和胜率。热力图以零为中性色；未提供/非完整月有独立标记，不能补成 0%。未闭合段单列，统计规则见第 4 节。
- **操作与结果：**点月份或持仓段，定位对应净值区间和交易链；用同一上下文查看收益是否集中于少数月份或少数持仓段。
- **缺失与 owner：**未保存汇总就显示不可用，不把成交笔数当完整交易数。账户统计由 Engine 提供；IC/ICIR 等信号评价由 Research 提供，按策略和标签适用性展示，并与账户统计分区。UI 不核算。**验收要求：**月份单位为%，盈亏分布单位与 owner 相同；平均收益的分母/权重可查；分子、分母、平局和开放段可见，点击关联准确。

![F05 月收益热力图与完整持仓段盈亏分布，合成示意](ui-prd-assets/figure05_monthly_segments.svg)

### F06 数据与运行信息

- **输入与展示：**owner 保存的依赖、数据版本、运行身份、质量说明和账户水位。主要限制用短句留在主视图；“数据与运行信息”默认折叠，展开后查看完整来源。
- **操作与结果：**展开某项、从图中点查、复制上下文摘要，得到对应来源与保存证据；运行状态、数据缺证和执行近似分别解释。
- **缺失与 owner：**来源不可读时保留已知身份并报缺口；校验失败阻止当作有效结果展示，旧缓存注明截止点。各 owner 提供自身证据，UI 组合只读投影。**验收要求：**切换/刷新不混旧侧栏，现金与持仓水位一致；浏览前后 owner 产物不变，无采集、训练、重跑或下单调用。

## 4 已确认的基准与统计规则

**市场基准：**默认沪深300，独立于策略 ETF 池；后续 A 股机器学习组合也沿用。首版冻结为 `000300.SH` 价格指数（不含分红），使用严格前一交易 session 作净值锚点，披露与账户含分红收益的差异；全收益系列后续单独定义。上证、纳斯达克为可选参考，旧策略作为版本对照。跨市场明示原币、交易日和评估范围；换汇与日历对齐由 owner 固定保存，UI 不补算。精确合同见 [Trade 日级 P10](04_axiom_trade.md#daily-evaluation)。

**完整持仓段与胜率：**单证券持仓 0→非0→0 为一个完整段，段内加减仓合并，费用及分红计入净盈亏。胜率为净盈利段数÷可统计闭合段数，平局保留；开放段、初始持仓无入场记录的左截断段、已知收入未确定段单列且不进分母。Engine 按登记日权益归属持仓段，EX 确认收入一次，PAY 只转现金。可选分红观察证据仅证明固定源已观察记录；缺证时 pending 未知显示 null、已知 pending 数明示为 known，不把未知总量补成已排除的零。已观测闭合段的统计仍可保存，范围限制必须展示。UI 不把一次成交当完整交易。

**月收益和平均收益：**年份×月份热力图显示 Engine 保存的账户月收益率（%）。冻结日历必须证明自然月边界及当月首末交易日覆盖；不能证明完整的首尾月显示 PARTIAL，正式收益为 null，局部 observed_return 另列，不用工作日推测完整性。平均段净收益率采用净盈亏÷累计买入成本（含费用），对可统计闭合段等权平均，同时展示平均段净盈亏（元）；它不是 IRR。比例使用 Engine decimal 原值只格式化%，整数金额以分保存、均值可含小数分；缺结果不补零。小样本先展示逐段已保存净盈亏；完整盈亏分布仍属首版目标，样本足够时由 Engine 保存固定桶边界、计数与纳入样本数，UI 只渲染。逐段柱图不能冒称分布功能已完成。

比较时核对期间、初始账户、价格、费用、分红与执行假设；日常只提示差异，细节折叠。短样本不补年化。复盘展示保存链，不把相关性写成信号因果。其余工程一致性由我们负责，不增加重复的用户选择题。

## 5 首版、后续与非目标

**首版范围：**完整只读路径，覆盖研究问题→版本→运行、共用收益风险/结果对比、交易下钻、月收益与持仓段、折叠的数据与运行信息。先连接已有结果，再接 owner 补齐的投影；缺失入口明确不可用。

**当前顺序：**①父任务核对已定功能与统一设计；②给用户看清晰、干净、配色协调的视觉草案，避免密集表格；③视觉对齐后按统一设计开发，owner 缺口先用固定小样本核对；④完整只读联动验收后再讨论部署。今天功能不再另设用户重审 PRD 的门槛，实质新取舍或设计矛盾才提出讨论。

**低优先级及后续：**决策 debug、多期/多模型图层、Qlib 适用信号诊断、阶段稳健性和大范围分页。**非目标：**采集、训练、自动研究、后台回测计算、改账本、真实下单、自动发布，以及软件承诺 alpha 或长期收益。

## 6 当前已有与接口缺口

截至本稿引用的[当前交付](../current-delivery.md)，真实固定 ETF 样本已保存净值、持仓、决策/委托/成交、六项运行汇总及来源版本；现有 UI 能生成只读静态结果报告，尚不是本 PRD 的交互产品。

本轮已冻结 [Research 问题/版本/运行、整理状态与只读投影](05_axiom_research.md#experiment-records)和 [Engine 固定基准、日回撤、月收益及持仓段 P10](04_axiom_trade.md#daily-evaluation) 的最小读取合同，实现状态与验收另记当前交付。Research Reader 返回保存说明、引用和显式版本差异；Engine 的 `load_backtest_evaluation` 仅读取/hash 校验已保存报告，UI 不调用 evaluate_backtest。Data OHLC 必须绑定该运行的固定 Snapshot/query。当前 Engine 账户保存的行情只有 open/close/volume，这不代表 Data 没有 high/low；适用信号评价及低优先级决策 debug 仍待补齐，当前 ETF 配方没有成熟标签或 IC 验收。

## 7 边界与未来部署约束

模块职责、输入、输出、消费者与不负责范围统一引用[总纲唯一模块边界表](https://github.com/sinnergarden/axiom-docs/blob/c22f49342b415290abc7d45d438e4d58013a1c45/docs/design/01_axiom_overview.md#module-boundaries)。本 PRD 的功能输入与验收说明仅应用该分工，不另维护一份边界规范，也不新增接口或计算职责。

UI 读取 Research 的 `experiment_projection_v1` 及 Engine 已保存的 `evaluation_report_v1`，不新建研究 registry、不写收藏或搁置状态、不重算统计。运行关联保留 Engine 原值 `run_id+content_digest`，评估关联额外保留 `evaluation_ref+evaluation_content_digest` 并匹配报告 input_run_ref。旧账户结果无 evaluation_ref，不能伪造该字段或覆写旧保存件。

**已确认的部署方向，尚未授权执行：**后台计算与存储在用户回测云；前端优先 Sites，若公开资格不支持则用 GitHub Pages 平台域名，无自有域名也可。第一版只读保存产物；后续再接 HTTPS 只读 API 和鉴权，密钥不放前端。公开 demo 与私有研究隔离，公开示例不携带私有结果。

具体读取通道、鉴权和托管配置仍待讨论。本稿不确认 Sites 公开资格，也没有实际部署、付费服务或公开研究数据的授权。

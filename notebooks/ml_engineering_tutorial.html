M1 操作页：共享输入，迭代模型，复用保存预测

1. 当前可以做什么

当前可以从固定输入保存模型与预测、改评价 Label、组合保存预测并交给 Engine；255 折预测和 7 份信号评价已有保存证据，五年账户验收结果待 Engine owner 回填。

按第 2–6 节选择一个动作。先确认配置和保存父件，再运行已有公共入口；模型迭代留在同一个 Data、Feature 和 Batch 会话里。结果由各 owner 保存，UI 读取保存值。

本页默认是阅读模式：查看说明、代码和第 7 节工程实测，不打开数据、不加载大账户、不训练。执行模式使用本地路径配置，显式选择模型、选列、评价或策略动作；执行成本与结果身份会随所选配置变化。

完整历史 Notebook及历史 HTML保留此前两折、旧版本限制、失败尝试和所有原输出。接口定义见Research 主章与Trade 主章；源码和审阅身份见版本表。

2. 六份配置分别改什么

配置 研究者修改的内容 由谁执行，影响哪些保存件
Feature registry 的特征定义、依赖、lookback、PIT 和 cutoff Research Feature producer 与 Core。公式变化生成新 Feature 父件；本页加载已有父件。
Label 收益起止 session、horizon、价格尺度、成熟规则 Label producer。训练 Label 变化需新 cohort；事后评价 Label 可固定原预测单独更换。
Dataset fold 日历、训练窗口、推理范围、时钟、model_feature_selection 和内存预算 load_stock_sequential_configuration 解析 schedule，原 preparation owner 保存 cohort。v2 周度 schedule 展开为原显式 folds。
Model TrainingSpec.parameters、seed、固定选择协议与资源 原 LightGBM 后端。同 cohort 的模型参数迭代可复用 Batch；只有完整定义相同才可能 HIT。
Signal 输入模型别名、截面归一化、固定权重与输出语义 build_stock_derived_signal 调用 Core，保留真实预测父引用；不训练。
Strategy 组合政策、调仓、执行规则、费用和初始账户 Engine。使用 owner 已冻结的 BacktestRequest；初始资金来自请求。

这些角色有独立 typed 配置。当前 stock 配置执行入口接收 Label、Model 和可选 Signal，Dataset schedule 另由配置文件引用。FeaturePlanSpec 和 StrategyRecipeDraft 可解析，但它们还不是这个入口的通用执行脚本；Feature 使用自己的 producer，Strategy 使用 Engine 的冻结请求。

experiment.yaml 的 specification_files 引用 Label、Model 及可选 Signal YAML，dataset_file 引用 Dataset schedule。改模型就换 Model 文件，改特征子集就改 Dataset 的选列；不要把已有 Batch 的选列在训练调用处偷偷换掉。组合两份模型时使用单独 Signal 配置，其别名与保存模型对应。

执行前在本地 JSON 填写 experiment_file、data_root、saved_feature、output_root 和 data_limits。复用 cohort 再提供 saved_batch；模型对照可提供 model_variants 文件列表。评价动作提供 model_session_file、evaluation_label_file，可选 evaluation_signal_file；策略可提供 owner 的 owner_handoff_file、strategy_request_file、runtime_options_file。这些是本地输入路径和预算，私人内容不写入教程。

设置 AXIOM_M1_LOCAL 指向该 JSON，再显式设置 AXIOM_M1_MODE=execute 与 AXIOM_M1_ACTION=models|selection|evaluation|strategy。下方代码只读取这些配置；refs 和 receipt 由实际 owner 产生。

3. 只打开一次共享会话

Data ColumnSource 负责固定版本的列式事实，Feature view 保留已有特征，Batch 保留已准备的训练与 OOS 输入。下面的薄上下文调用原 owner API；它不新增缓存、调度器或特征执行器。Snapshot 和 PIT 从保存 Feature 读取，模型循环不重新打开 ColumnSource。

shared_session 在本次动作结束时关闭 owner。同一次会话内可在共享输入上完成多次模型调用；离开会话后，后续打开仍要支付冷核验成本。新特征子集通过原 preparation owner 建立新 cohort，不能沿用旧 cohort 的成员掩码。

from contextlib import contextmanager


@contextmanager
def shared_session(options):
    require_execution()
    from axiom_data import Data
    from axiom_research import load_stock_sequential_configuration, load_stock_feature_view

    configured = load_stock_sequential_configuration(options["experiment_file"])
    dataset = configured["dataset"]
    preparation = dataset["preparation_options"]
    limits = {"maximum_matrix_bytes": preparation["maximum_resident_bytes"]}
    for name in ("maximum_source_bytes", "maximum_parent_bytes"):
        if name in preparation:
            limits[name] = preparation[name]
    data = Data(options["data_root"])
    with load_stock_feature_view(options["saved_feature"], limits=limits,
                                 residency="sequential") as feature:
        saved_spec = feature.to_dict()["spec"]
        fact_spec = {name: saved_spec[name] for name in ("snapshot", "pit_policy")}
        del saved_spec
        with data.open_column_source(snapshot=fact_spec["snapshot"],
                                     limits=options["data_limits"]) as source:
            yield {"data": data, "source": source, "feature": feature,
                   "fact_spec": fact_spec, "configuration": configured, "configuration_path": options["experiment_file"],
                   "limits": limits, "output": Path(options["output_root"])}

4. 换模型参数，或换 Feature 子集

只改模型参数时，先载入一份 COMPLETE Batch，再依次读取 Model YAML。每个模型调用都使用同一个 Batch；writer 冻结各自的 OOS 输入，完整定义相同的保存模型可以复用。下方模型入口保存 fold 路径与原 owner 返回的 ArtifactRef，便于下一节评价。

改 model_feature_selection、训练 Label 或窗口时，选 selection 动作，由已有 configured producer 创建新 cohort，并返回含 prediction_bindings 的完整交接。该调用继续借用本会话的 Feature 和 ColumnSource。公式变化则先用原 Feature producer 保存新父件，再替换本地 saved_feature。

Model-only 循环输出的 raw fold 与 OOS 引用用于评价。账户输入使用 configured producer 已保存的 prediction_bindings，或第 5 节 DerivedSignal 的公开交接，不手工拼 raw 模型绑定。

def iterate_saved_models(session, *, batch_file, model_files=None):
    require_execution()
    from time import perf_counter
    from axiom_research import (load_stock_experiment_specs, load_stock_ml_batch_inputs,
        build_stock_ml_fold_from_saved_inputs, open_stock_signal_evaluation_freeze, to_dict)

    manifest = read_json(batch_file)
    scope = session["configuration"]["dataset"]["scope"]
    models = {}
    variants = ([load_stock_experiment_specs([path])["specs"]["model"] for path in model_files]
        if model_files else [session["configuration"]["specification"]["specs"]["model"]])
    with load_stock_ml_batch_inputs(manifest, feature_inputs=session["feature"],
                                   limits=session["limits"], residency="sequential") as batch:
        for number, spec in enumerate(variants):
            alias = "model_" + str(number + 1)
            started = perf_counter()
            folds, metrics = [], []
            with open_stock_signal_evaluation_freeze(batch, scope=scope,
                    destination=session["output"]/"oos", signal_name=alias) as writer:
                for item in manifest["folds"]:
                    calls = {}
                    run = build_stock_ml_fold_from_saved_inputs(item["input_manifest"],
                        fold_spec=item["fold_spec"], batch=batch, training_spec=spec,
                        destination=session["output"]/"folds", metrics=calls)
                    folds.append(str(run.path))
                    metrics.append(calls)
                frozen = writer.finish()
            frozen_wire = to_dict(frozen)
            scope = read_json(frozen_wire["uri"])["scope"]
            models[alias] = {"model_name": spec.name, "fold_paths": folds,
                "raw_evaluation_input": frozen_wire,
                "seconds": perf_counter() - started, "metrics": metrics}
    return {"scope": scope, "models": models}

        session["output"].mkdir(parents=True, exist_ok=True)
        (session["output"]/result_name).write_text(
            json.dumps(result, ensure_ascii=False, indent=2) + "\n")
        print("已保存：", result_name)

5. 固定预测，换评价 Label 与组合

训练目标与事后评价目标各自固定。已有 5D 预测可以用独立 3D Label 做事后统计；评价 producer 读取固定 Snapshot 的实际端点，保存成熟性、缺值和来源证据。模型、预测和原训练 Label 保持原值。报告分别给出各信号自然覆盖与共同有效样本，IC/RankIC 由原 Core 计算。

freeze_label_and_combinations 从 writer 保存的 OOS 控制件直接复用原 signal_inputs，Label descriptor 由公共 producer 返回；用户无需写 receipt 或 digest。该例通过已有 multi-owner 入口显式登记这一份 COMPLETE Batch；函数从 owner 与原预测产物读取实际引用，生成必要映射。跨 cohort 时应保留每个原 owner 并登记对应预测，不混用成员掩码。

组合时读取 typed SignalPlan，将别名映射到真实保存 fold。选择可选的 evaluation_signal_file 后，下面的 combine_one_fold 使用 Dataset 中 owner 已冻结的该 fold 时钟，调用原 Core 的归一化和固定加权路径；别名使用保存模型的 model_1、model_2 等键。多个 OOS fold 按保存顺序逐次组合，不能拼接重叠日期。原 Data/Feature/Batch 关闭后，组合与原预测进入同一公共保存评价入口。组合的公开 engine_input_binding() 另保存为策略交接，供第 6 节使用。

def freeze_label_and_combinations(session, saved_models, *, label_file, batch_file, signal_file=None):
    require_execution()
    from axiom_research import (load_stock_experiment_specs, load_stock_ml_batch_inputs,
        build_stock_evaluation_label_inputs, save_stock_signal_evaluation_inputs)

    scope = saved_models["scope"]
    label = load_stock_experiment_specs([label_file])["specs"]["label"]
    inputs, derived_paths, bindings = {}, [], []
    for alias, model in saved_models["models"].items():
        root = read_json(model["raw_evaluation_input"]["uri"])
        original = root["admission_receipt"]["signal_inputs"]
        if list(original) != [alias] or root["scope"] != scope:
            raise ValueError("Saved OOS alias/scope does not match this model session")
        inputs[alias] = original[alias]
    plan = load_stock_experiment_specs([signal_file])["specs"]["signal"] if signal_file else None
    aliases = [item.alias for item in plan.inputs] if plan else []
    if plan and (not set(aliases) <= set(saved_models["models"]) or
                 len({len(saved_models["models"][a]["fold_paths"]) for a in aliases}) != 1):
        raise ValueError("Signal aliases must name matching ordered saved model folds")
    with load_stock_ml_batch_inputs(read_json(batch_file),
            feature_inputs=session["feature"], limits=session["limits"],
            residency="sequential") as batch:
        fact_spec = session["fact_spec"]
        labels = build_stock_evaluation_label_inputs(session["data"],
            snapshot=fact_spec["snapshot"], pit_policy=fact_spec["pit_policy"],
            label_spec=label, scope=scope, column_source=session["source"],
            destination=session["output"]/"evaluation-labels", limits=session["limits"])
        frozen = save_stock_signal_evaluation_inputs(inputs, raw_label_input=labels,
            scope=scope, owner_batches={batch.identity: batch},
            prediction_owner_refs={item["signal_run_ref"]: batch.identity
                for items in inputs.values() for item in items},
            limits=session["limits"], destination=session["output"]/"evaluation-inputs")
        if plan:
            for number in range(len(saved_models["models"][aliases[0]]["fold_paths"])):
                saved = combine_one_fold(session, signal_plan=plan,
                    fold_paths={a: saved_models["models"][a]["fold_paths"][number] for a in aliases},
                    batch=batch)
                derived_paths.append(str(saved.path))
                bindings.append(saved.engine_input_binding())
    return {"input_ref": frozen, "derived_paths": derived_paths,
            "prediction_bindings": bindings, "scope": scope}


def combine_one_fold(session, *, signal_plan, fold_paths, batch=None):
    require_execution()
    from axiom_research import load_stock_ml_fold, build_stock_derived_signal

    first = load_stock_ml_fold(next(iter(fold_paths.values())), batch=batch).to_dict()
    spec_ref = first["definition"]["fold_spec_ref"]
    contexts = session["configuration"]["dataset"]["signal_contexts"]
    if not isinstance(contexts, dict) or spec_ref not in contexts:
        raise ValueError("Use the owner-saved Signal context for this fold in Dataset")
    return build_stock_derived_signal(signal_plan, prediction_inputs=fold_paths,
        context=contexts[spec_ref], destination=session["output"]/"derived", batch=batch)


if EXECUTE and ACTION == "evaluation":
    from axiom_research import (save_stock_derived_signal_evaluation_inputs,
        evaluate_stock_signal_input_periods, to_dict)

    print("已保存年度：", sorted(reports["by_year"]))

6. 复用预测跑策略，再只读账户

选择 Engine owner 冻结的策略请求，保留请求的初始账户、市场、费用和时钟。owner_handoff_file 使用 configured producer 已保存的交接 JSON；下方只把其中原 prediction_bindings 交给已有 request adapter。Market 在策略会话准入一次，账户由唯一 Runtime 执行。该动作不调用 supplier、Feature、fit 或 predict。

runtime_options_file 是 owner 已冻结的资源参数，包含 block_sessions、limits、max_market_bytes 与 max_signal_bytes。选择新策略与新结果目录，避免覆盖旧账户。公开 StrategyRecipeDraft 目前不会自动翻译成账户请求，因此这里直接使用现有 Engine 合同。

当前五年账户结果：待回填。待 owner 保存后，在本地增加 saved_account_file 和 saved_evaluation_file，通过公开 loader 读取。读取与重新执行账户是独立动作；本页没有把已完成 Research 预测称作账户验收。

当 owner 提供原 Native delivery 时，runtime_options_file 的 native_views 列表给出 directory、manifest_sha256 和 limits；下方沿已有 open_native_view 与 StockNativeViewSource 准入，不寻找并不存在的 logical-batches JSON。真实短账户还需要与原 profile/rules 和 Native query 完全匹配的范围；五年原件不能直接裁成一周并沿用身份。

六日短范围已沿既有公开 factory 和固定 Snapshot 生成匹配的 Native/profile/rules。实际 strategy 消费新范围身份的 Research 组合交接，保存 COMPLETE 账户并通过公共 projection 读回；原初始资金和费用保持原值。完整五年结果仍待 owner。

def consume_saved_predictions(handoff, *, request_file, runtime, destination):
    require_execution()
    from contextlib import ExitStack
    from axiom_engine.runtime import (BacktestRequest, StockInputSource, StockNativeViewSource,
        StockMarketSpec, admit_stock_market_inputs)
    from axiom_research import stock_request_with_saved_predictions, run_saved_stock_strategy

    original = BacktestRequest.from_dict(read_json(request_file))
    request = stock_request_with_saved_predictions(original,
        prediction_bindings=handoff["prediction_bindings"])
    with ExitStack() as owners:
        if runtime.get("native_views"):
            from axiom_data import open_native_view
            handles = [owners.enter_context(open_native_view(**item))
                for item in runtime["native_views"]]
            source = owners.enter_context(StockNativeViewSource(native_views=handles,
                max_active_bytes=runtime["limits"]["max_block_bytes"],
                **runtime.get("source_options", {})))
        else:
            source = StockInputSource(**runtime.get("source_options", {}))
        with admit_stock_market_inputs(StockMarketSpec.from_request(original), source=source,
                block_sessions=runtime["block_sessions"], limits=runtime["limits"],
                max_market_bytes=runtime["max_market_bytes"]) as market:
            return run_saved_stock_strategy(request, market=market, source=source,
                destination=destination, block_sessions=runtime["block_sessions"],
                limits=runtime["limits"], max_signal_bytes=runtime["max_signal_bytes"])

8. 固定长周期入口、预算与剩余验收

固定长周期继续使用第 4 节的 selection 入口：stock_dataset_schedule_v2 从保存 Feature axes 编译周度 folds，再由 build_configured_stock_sequential_experiment 在同一 ColumnSource 和 Feature 会话内逐 fold 准备、训练和冻结。原显式 v1 schedule 仍可使用。现成保存 case 的交易范围为 2019-07-01—2024-06-28，已有保存件覆盖 255 折预测与 7 份信号评价；无需为每个模型重新打开数据 owner。只改 Model 时走 models 动作复用 COMPLETE Batch，固定预测的评价和账户消费分别走第 5、6 节。

预算所在配置 控制什么
Dataset preparation_options maximum_resident_bytes 限定准备与矩阵工作额度；maximum_source_bytes、maximum_parent_bytes 限定来源与父件；row/column block 控制分块。
本地 data_limits cache_bytes、max_working_bytes 限定 ColumnSource 缓存和工作额度，缓存已经包含在工作额度内。
